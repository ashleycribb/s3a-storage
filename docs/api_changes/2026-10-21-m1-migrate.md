# 2026-10-21 — M1: legacy `.s3a` migration (`s3a-cli migrate`)

**What changed.** New module `s3a_engine::migrate` (`migrate_file(input, output, dry_run)`) and CLI
command `s3a-cli migrate <in_file> <out_file> [--dry-run]`. No existing on-disk format, reader or
writer behavior changed. Core (`s3a-core`) is untouched.

**Supported source versions** (reconstructed from git history, not invented):

| Version | Where it comes from | How it differs from current |
|---|---|---|
| v1.0 | `TileWriter` at commit `66f70c4` | `SimplexHull` was 216 bytes (`_reserved: [u32; 4]`), so filter/provenance/lifecycle/security/encoding/learned_index sit 8 bytes later (264..488) and 488..512 is `_padding`; tile `header_crc32` covers only bytes `0..36`; `record_layout_version` was `_reserved1 = 0`; file `addon_mask`/`file_uuid` were `_reserved2 = 0`. Current readers fail `verify_checksums` on these files. |
| v1.1-unaddressed | spec "Legacy Compatibility Path" | Current layout and CRCs, but `file_uuid == [0, 0]` and `record_layout_version <= 1`. |

The hull change landed in `395c196`. The fixture
`crates/s3a-engine/tests/fixtures/legacy_v1_0_telemetry.s3a` was written by running the real v1.0
`TileWriter` from `66f70c4` (2 telemetry tiles x 5 records).

**Guarantees.**
- Never in place: refuses `out == in` and refuses an existing output.
- Rejects corrupt input (header CRC matching neither rule, payload data CRC mismatch, truncation,
  non-zero bytes that v1.0 reserved, mixed versions, edge-profile files, already-current files).
- Payload bytes are copied unchanged. The output gets a fresh `file_uuid`, per-tile
  `tile_index`/`generation`/`file_uuid`, `record_layout_version = 1` and current CRCs.
- Writes `<out>.migrate-tmp`, fsyncs, re-opens it with `MmapReader`, runs `verify_checksums`,
  checks each tile's type, record count and payload SHA-256 against the source, then
  `fsutil::atomic_replace` into place. On any failure the temp file is removed.
- `--dry-run` does all checks in memory and writes nothing.
- The source file SHA-256 is printed for provenance (there is no manifest in a plain file to store it).

**For agents applying merges.** Do not change `HyperTileHeader` layout or CRC rules without adding a
new `LegacyVersion` and a fixture generated by the old code.
